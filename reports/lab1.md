# Problems
## Problem 01

请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

**My Answer**

---

一个页表项的大小为 8 字节，由物理页号和标志位组成。其中物理页号占据页表 [10, 53] bit 的位置。在 SV39 页表中，使用 9 位表示某一级页表的索引，因为一页的大小为 0x1000 字节，0x1000 / 8 = 0x200 = 1 << 9，因此某一级页表的数组长度为 512 时，该页表刚好占据一个物理页。最低 8 位代表该页表项的属性。属性的作用按 bit 位从低到高分别为：

- V: Valid，该页表项是否有效
- R: Readable，该页是否可读
- W: Writable，该页是否可写
- X: Executable，该页是否可执行
- U: User available，该页是否在U态可访问
- G: 不重要
- A: Accessed，自从该项被清零后，该页是否被访问
- D: Dirty，自从该项被清零后，该页是否被写入

## Problem 02
缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

- 请问哪些异常可能是缺页导致的？
  - Answer: 内存访问异常。当内存中找不到虚拟地址对应的物理地址时，就会触发内存访问异常，这是缺页导致的。
- 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
  - Answer: 缺页发生时，内核会触发中断，因此`sstatus`的`SPP`会被设置为 U 。`sepc`会设置为触发中断的 U 态访存指令，`scause`会保存缺页中断对应的指示码，`stvec`保存中断的开始地址等。

缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

- 这样做有哪些好处？
  - Answer: Lazy 策略可以减少不必要的操作，可显著提高内存的使用效率。

其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

- 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
  - Answer: 在本实验中，实现的 SV39 页表实际上不全，因为最高一级页表的位数太多，实际使用到的只有最高一级页表的最低 9 位，如此一共 3 级页表可以索引到 1 << (9 * 3 + 12) = 1 << 39 = 512GiB 空间。为方便计算，这里认为题目使用的是 GiB 而不是 GB。10GiB 空间需要 1 个第一级页表，一个页表占据 8 * 512 = 4KiB 内存。第 1 级页表中需要添加 10GiB / (1 << 9 * 2 + 12)B = 10GiB / 1GiB = 10个有效的第二级页表，这些页表一共占用 10 * 4KiB = 40KiB。每一个第二级页表包含 512 个有效的第三级页表，一共占用 512 * 10 * 4KiB = 20MiB。故这些页表一共占用了 20MiB + 44KiB 空间，数量级为 10^7^ 量级。

- 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。
  - Answer: 可以维护一个有序的 B 树，在用户进行内存申请时，首先将申请的页记录到树中，访问时若出现缺页异常，首先到 B 树中查找要访问的内存是否包含在待分配的页中，若是，则执行分配并完成访存。若否，则说明本次内存访问无效。

缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

- 此时页面失效如何表现在页表项(PTE)上？
  - 此时对应的物理页在内存中已经不存在，因此 PTE 中的物理页号应该被设置为 0。

## Problem 03

双页表与单页表

为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说，用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 KPTI )

- 在单页表情况下，如何更换页表？
  - Answer: 在单页表中，可以将不同用户进程的页表保存在多个不同的较高等级的页表项之下，使得不同用户进程和内核空间的页表项位于不同的页表之中。创建进程前可建立页表与进程的对应关系，在更换页表时直接切换到对应的页表即可。
- 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）
  - Answer: 可设置内核页表的 U 位为 0，使得用户态无法访问内核页表，也就无法找到内核页内容。
- 单页表有何优势？（回答合理即可）
  - Answer: 方便统一进行管理。
- 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
  - Answer: 在 CPU 状态改变时，需要更换页表。对于单页表操作系统，需要在进行系统调用时更换页表。
